# The safety model

sqldoro makes the dangerous statements hard, in layers. Every statement, whether typed, run from the
history, or generated by the grid, goes through the same guard before anything runs.

- **Read-only connections** (the default) refuse anything that may write, and the database session
  is opened read-only too, so a write the guard misses still fails on the server.
- **UPDATE or DELETE of every row** waits until you type the table name.
- **Production** connections ask you to type the connection name before any write or schema change.
- **Manual transactions**: switch an editor to manual mode, then commit or roll back yourself.
- **Automatic LIMIT** on queries that would read everything.

## What it cannot do

The statement classifier is best effort: it cannot see what a stored procedure, a trigger or a
function does, and it fails closed on what it does not understand. **The permissions of the database
user are the real guarantee.** Connect with the least privilege the work needs: a read-only role for
browsing production, and writes only where you mean to change data.

sqldoro has no telemetry: it talks only to the databases you configure.
